# 电量与费用定义

id为计量号、order为订单号、station为站点，均为字符串。kind取order或station。计量start/end必须带时区，区间[start,end)，最大72小时可调至168小时。energy以kWh或MWh输入，输出kWh。未知哨兵不等于零。
费率版本以本地+08日期[from,to)生效；日内时段必须完整无重叠覆盖0–24小时。默认11月17日调整尖峰价，可在API参数tariffs中提供相同结构版本清单。
计量段内假定匀速用电，电量按时长交集分配，最后一段修正Decimal除法尾数保证电量严格守恒。跨日以当地日期重选版本。
每站唯一总表电量减订单电量为损耗，按订单kWh占比分配。总表缺失、重复、负损耗或无订单承接损耗时标记异常，不强行分配。
订单应收=各分时电量×费率+损耗份额×loss_rate。先算站总额再最大余额分币，稳定id打破余数并列。JSON金额为Decimal字符串。账单bill为CNY，差额=应收-bill，容差边界包含。
版本最高者采信，同版冲突全部隔离；重复和旧版计入隔离。输入行数=采信+隔离。批次哈希包含输入摘要、规则版本、参数；复核乐观锁防止旧提交覆盖。

站点总表区间必须覆盖其全部订单区间；未覆盖标记总表未覆盖订单区间，损耗不强制分摊，账单结论为待复核。

## 补读派生

补读文件列：`id,station,start,end,energy,unit,version,source`。`source` 取 `主表` 或 `后备表`（兼容 `main`/`backup` 等写法）；`kind` 可省略，一律按总表读数处理，订单行与来源不明的行进入隔离。一次补读只能属于一个站点。

合并规则：主表读数优先占用时段，后备表只填主表未覆盖的时段，因此首尾相接的读数自动拼接；重叠部分按交集时长比例折算后隔离，原因码 `OVERLAP`，不重复计入电量。原批次的总表读数只保留补读未覆盖的部分（来源记为 `原表`），原批次本身不被修改。

当前账：每个站点只有一个指针，指向原批次或某个派生版本。派生版本依次经历 `待核对`（合并完成）、`已核对`（核对通过）、`当前`（已切换）、`已替换`（被更新的版本替换）、`核对失败`。只有 `已核对` 可切换；切换与写入新账在同一事务内，失败则回退指针并恢复旧版账单，历史写入 `current_history`。`恢复旧版账单` 可切回上一版本或指定旧账，原批次始终可查。

核对关：单站损耗判定必须为通过且非负；其他站点损耗必须与原批次一致；合并后不得存在重叠时段；补读电量必须守恒（采信=读数-隔离）；补读区间不得超出原总表与订单覆盖范围。确认按本地（+08:00）自然日逐段进行，中断后从最后确认时段继续；版本标识按原批次、站点与补读内容指纹生成，等价写法（行序、编码、`Z`/`+08:00`、`30`/`30.0`）复用同一版本。
