# 充电桩分时电价与损耗结算

使用者：充电站财务核算员。接收计量间隔与订单，按实际时段重算电费及站内损耗。

核心规则：电量按计量段与费率区间交集时长分配，跨日费率按当地日期选择，未知电量不作零，损耗分到分。

## 启动

```sh
docker compose up --build -d
docker compose exec -T app pytest -q
docker compose config --quiet
```

浏览器访问 http://localhost:18202 。首页已装载脏样例，可编辑CSV与参数后运行，也可上传文件。七个导航分别对应业务步骤。

## 模块

- M1 电量接收：接收订单及总表计量，入口 `/m/1`、`GET/POST /api/m1`。
- M2 费率版本：校核费率版本与单位，入口 `/m/2`、`GET/POST /api/m2`。
- M3 订单切段：按时段交集拆分电量，入口 `/m/3`、`GET/POST /api/m3`。
- M4 站内损耗：按站点分配总表损耗，入口 `/m/4`、`GET/POST /api/m4`。
- M5 费用重算：精确计算并分配分币，入口 `/m/5`、`GET/POST /api/m5`。
- M6 账单对照：对照账单与损耗异常，入口 `/m/6`、`GET/POST /api/m6`。
- M7 结算批次：核对电量行数并复核，入口 `/m/7`、`GET/POST /api/m7`。
- M8 补读派生：由原批次派生关联版本，按时段合并主表与后备表并隔离重叠读数，核对通过后切换唯一当前账，入口 `/m/8`、`/api/m8`。

## 补读派生（M8）

主表停电期间由后备表补读，补读后同一站点会同时存在主表与后备表读数，可能出现首尾相接和少量重叠。M8 不修改原批次，而是从原批次派生关联版本：

1. 在 `/m/8` 选择原批次，提交补读 CSV（列：`id,station,start,end,energy,unit,version,source`，`source` 为主表或后备表，`kind` 可省略并固定按总表处理）。
2. 按时段合并：主表优先占用时段，后备表只填未覆盖时段；重叠部分按交集时长比例隔离并保留原因码 `OVERLAP`，不会重复计电。首尾相接的读数自然拼接。
3. 原批次总表读数只保留补读未覆盖的部分，因此旧读数不会被悄悄改掉。
4. `POST /api/m8/<id>/check` 在合并账上重跑切段、损耗、费用与账单；只有单站损耗通过、其他站点损耗不变、电量守恒、区间不越界时才标记为 `已核对`。
5. `POST /api/m8/<id>/activate` 才切换唯一当前账。切换失败（含新账写入异常）自动恢复旧版账单，并记录切换历史；`POST /api/m8/<id>/restore` 可随时恢复旧版，原批次始终原样可查。
6. 确认按本地日逐段落库；中断后再次提交同一份补读会从最后确认时段继续。相同内容（行序、编码、`Z`/`+08:00`、`30`/`30.0` 等等价写法）只生成一个版本。

`GET /api/m8/<id>/evidence.csv` 同时导出合并后读数、重叠隔离、补读隔离、原批次损耗与当前账指针。电价政策与费率版本未改动，也不产生真实收费。

1. 运行默认样例，核查隔离原因与业务合计。
2. 修改CSV单元格或参数并重跑，保留行号与输入摘要。
3. 在最后一步复核，旧版本提交返回409。
4. 证据CSV包含采信行和隔离行，重跑相同内容复用批次。

## 数据与目录

`app/modules/` 按业务切分；`sample_data/` 为UTF-8 BOM、GB18030及干净/脏样例；`tests/` 含规则与端到端测试。SQLite保存运行与复核，命名卷records保留重启后的记录。若需从头开始，可先停止服务并在确认不再需要记录后删除该项目records卷。

## 定义与边界

计量段内假定匀速用电，站点总表必须唯一且覆盖所导入的全部订单；真实采样差异应预先切成计量段。只计算电费及损耗，不含停车服务费。

详细字段、计算定义与原因码见 `docs/DATA-DICTIONARY.md`，回归证据见 `docs/DEPTH.md`。
